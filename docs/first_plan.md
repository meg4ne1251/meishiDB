## OCR機能について

### 処理フロー
```
撮影・スキャン → 画像前処理（傾き補正・2値化）→ OCRエンジン（AI文字認識）
→ フィールド分類（氏名/社名/TELなど）→ DB保存
```

### 精度向上のアプローチ
- AI自動補正（学習ベースの誤字修正）
- オペレーター確認（人による目視チェック）
- 組み合わせで最大99.9%精度を実現

### OCRが苦手なケース
- 手書き文字（走り書きメモ等）
- デザイン名刺（色背景・斜め文字）
- 多言語混在（日英中が混ざる名刺）
- 縦書き・文字詰め

### 精度を上げるスキャン条件
- 解像度：200〜300dpi
- モノクロ推奨
- 傾きなし
- コントラスト強調

## OCRにGPUは必要か？

- **従来型エンジン（Tesseract等）はCPUのみで動作**
- AI/Transformerベースのモデルは速度のためにGPUがあると望ましい
- **クラウドAPI（Google Vision、AWS Textract等）はGPU不要**（クラウド側が持つ）

---

## セルフホストOCRの選択肢

| 選択肢 | GPU | コスト | 精度 | 備考 |
|---|---|---|---|---|
| Tesseract | 不要 | 無料 | △〜○ | CPU特化、日本語はやや弱い |
| PaddleOCR (PP-OCRv5) | あると速い・なくてもOK | 無料 | ◎ | **今回の採用候補** |
| EasyOCR | あると大幅高速化 | 無料 | ○ | CPUでも動く |
| GOT-OCR 2.0 | GPU推奨 | 無料 | ◎ | 名刺にはオーバースペック気味 |
| Google Vision API | 不要（クラウド） | 月1000枚無料〜 | ◎ | セルフホスト不可 |

## 採用方針：PaddleOCR PP-OCRv5 server（CPU動作）

### 採用理由
- 日本語・英語・中国語を1モデルで処理可能
- serverモデルは最高精度
- CPU動作可能（GPUより遅いが名刺1枚なら10〜30秒程度で実用的）
- OSSかつDockerで簡単にデプロイ可能

### 推定処理時間（名刺1枚）
- **GPU：1〜3秒程度**
- **CPU（ML350 Xeon E5系）：10〜30秒程度**
- ※名刺の文字量は50〜150文字程度なので1時間はかかりない

### 想定構成
```
名刺画像
  → PaddleOCR 3.0 (PP-OCRv5 server, CPU推論)
  → 氏名 / 会社名 / 電話番号 / メール を JSON で返す
  → 名刺管理アプリのバックエンドに取り込む
```

### デプロイイメージ
- Proxmox上のVM1台にDockerで立てる
- REST APIとして他サービスから呼び出す形が理想的
